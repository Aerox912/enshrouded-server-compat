## Decision and guarantees

Production now accepts native Windows AMD64 19041..26100 plus SINGLE exact build26300. 19040,26101,26299,26301 are rejected by the tested predicate. The existing Wine/native machine, complete pinned file SHA256, mapped PE identity, original dispatcher/neighbor bytes, CPUID CMPXCHG16B, page/protection/cache, bounded fixed Nt snapshot and thread-context checks are unchanged. The isolated fixture bypass remains SELFTEST-only and absent from production symbols. Build26300 approval is the parent's private-candidate decision based on G-INSTALL12/VERIFY49B evidence, not a future-build range.

G-INSTALL12 whole-block CAS128 and fail-closed retained suspension/gate/backing ownership remain unchanged. No site can thaw without complete original/installed byte, cache and original-protection proof. Both pinned sites occupy offset5 in an aligned16-byte block; their neighbor proofs remain frozen. Logical disable does not unpatch or release the slot, pinned modules, context or owned handles.

New process_install_service() returns the only constructible production InstallService, with private construction/destruction and process-lifetime storage. Outside DllMain/loader lock, start(EntryProof) pins the service code module, precreates recovery and launch events, creates the persistent worker and records EVERY handle before releasing its launch barrier. The service never cancels, joins, closes these live handles or exits its worker. The worker exclusively calls install() and recover_retained() on the same thread. When recovery_required is true (including zero-peer holds), it performs at most3 recovery calls per batch, then waits in the kernel for a signal or1000ms before another bounded batch. It never calls runtime, allocation, CRT logging, loader, MinHook or user error callbacks in that interval. Unexpected kernel wait failure executes intrinsic fail-fast; it does not resume threads or return to game code. Permanent failure can therefore leave the process quiesced indefinitely; exact ownership remains accessible and the worker remains available. This is an explicit operational failure, not successful startup.

Service snapshots use one lock-free64-bit atomic; state/readiness flags and event publication are lock-free too. Only safe_to_report()==true authorizes normal diagnostics or runtime stop/drain. It means settled without recovery_required; checking pending_suspends==0 alone is insufficient. ready(image) additionally requires exact image, complete published site, zero pending suspends and complete RuntimeAcceptance. disable() immediately removes runtime acceptance, never cancels recovery. request_recovery() only signals the precreated event; it cannot move recovery to its caller.

EntryProof assertions belong to the runtime owner: full pinned file verification, actual loaded callback/query/state/Dive anchors matching that file, and the matching real CALL/FRAME bridge. All default false. These assertions are prerequisites, not replacements for the installer's independent proof. RuntimeAcceptance requires verified original routes, a current binding provider and explicitly accepted native phase ordering; all default false. If those cannot be established, G stays off.
